## system

SBML (Systems Biology Markup Language) + SED-ML (Simulation Experiment Description Markup Language) + COMBINE archive (OMEX), with CellML as the physiology-focused sibling — the COMBINE family of open XML standards for exchanging and replaying computational biology models.

## overlap

The COMBINE stack is the closest existing answer to the proposed product's "typed declarative model + delegated simulation + replay receipt" triad, for one domain (biochemical/physiological modeling). Mechanisms: (1) SBML is a typed declarative model representation — species, compartments, parameters, reactions, events, rules, with math as MathML and units built compositionally from SI base kinds (UnitDefinition); models are checked against numbered validation rules (identifier consistency, MathML consistency, unit consistency), the analog of the product's compile-time validation. Level 3 is modular: core + optional packages (fbc, qual, comp, distrib, spatial…), i.e. capability declaration per model. (2) SED-ML is the experiment-description half: it references models (by URI), applies declarative model changes (XPath-targeted), names the simulation algorithm by KiSAO ontology term with algorithm parameters (tolerances, step sizes also as KiSAO terms), defines tasks/repeated tasks/parameter-estimation tasks, data generators and outputs — the direct precursor of the product's "solver obligation" object. (3) The COMBINE archive (OMEX, spec v1, 2014) is the receipt container: a zip holding model + SED-ML + data, a manifest.xml typing every entry by format URI, plus RDF metadata files — one file to reproduce a modeling project. (4) BioSimulators is the orchestrator analog: a registry of containerized simulation tools exposing a standard CLI that consumes COMBINE archives, with a conformance test suite verifying each tool's actual SED-ML/OMEX capabilities — solver identity, capability declaration, and uniform invocation, exactly the product's typed-external-solver pattern. (5) Annotation via MIRIAM/identifiers.org URIs, SBO and KiSAO ontologies is the analog of controlled vocabulary resolution, and BioModels (1,096 manually curated models seen today) demonstrates a curation pipeline that re-runs models before accepting them. What the stack does not attempt at all: logical inference, proof objects, symbolic mathematics, or a verdict/disposition result taxonomy — it standardizes descriptions and delegates all semantics to tools.

## insufficiency

Concrete missing mechanisms, not ambitions: (1) Units are optional and advisory — SBML explicitly makes unit declarations optional, requires models to be "numerically self-consistent independently of unit declarations," and unit-consistency checks (rule series 105xx) are warnings, not errors; there is no fail-closed dimensional gate. (2) No inference layer of any kind: SBML/SED-ML are data schemas; nothing derives, proves, or checks entailment; there are no proof objects and no result taxonomy — a simulation just emits numbers/plots, and failure modes (non-convergence, out-of-regime, backend absence) have no standardized encoding. (3) Receipts are incomplete: the OMEX manifest types files but mandates no content hashes; SED-ML names an algorithm (KiSAO) but not a solver implementation or exact version; seeds are not mandatory; BioSimulators documented tools whose emitted SED-ML "indicate different algorithms than what the simulation tool actually used." (4) Annotation is advisory RDF: MIRIAM URIs are optional, unchecked at "compile time," and can dangle or go stale; undeclared vocabulary is not an error anywhere. (5) Model changes target XML via XPath — syntactic coupling to serialization, brittle under refactoring, with no typed addressing of model entities. (6) Domain scope is biochemistry-shaped (species/reactions/compartments); general math/physics/chemistry claims are only expressible as raw MathML with no domain typing. (7) Conformance is voluntary: tools implement subsets (no repeated tasks, no subdirectories in archives, no model changes), so a valid archive is not executable everywhere. (8) Uncertainty: the distrib package can attach distributions, but there is no first-class separation of measurement/numerical/parameter/structural uncertainty and no evidence/claim typing.

## narrowing_history

Three different trajectories. SBML never narrowed — it was scoped to biochemical network models from the start (2000) and instead widened via Level 3 packages; the failure mode is stalled widening: the Arrays and Dynamic Structures packages are still listed as drafts on sbml.org years after proposal, and core has not moved past L3V2 (2019) — ambition outran implementer capacity. SED-ML narrowed deliberately at birth: conceived to encode the full MIASE reproducibility guidelines, L1V1 (2011) restricted itself to time-course simulations of already-published models, then re-expanded over 13 years (repeated tasks, steady-state, L1V4 2021 parameter estimation, L1V5 2024 generalizing tasks/changes/ranges/outputs via KiSAO) — evidence that the community judged a small executable core the only shippable unit. CellML genuinely narrowed: CellML 2.0 (released 2020-04-17) removed the reaction element and its children and other secondary features from 1.1, shrinking the language to components+variables+math+units+imports because the richer biochemical semantics were unimplemented and duplicated SBML's niche; governance moved to a Specification Custodian Board (announced 2026-05-19). The shared pattern: every widening beyond what reference implementations could execute either stalled (SBML packages) or was later amputated (CellML reactions).

## license

The formats are open, freely implementable community specifications (COMBINE standards); I could not verify a stated SPDX license on the specification documents themselves (sbml.org, sed-ml.org, cellml.org, and the combine-org/combine-specifications repo pages fetched today show no explicit spec license — evidence-incomplete). Reference implementation libSBML is LGPL-2.1 (verified on github.com/sbmlteam/libsbml, 2026-08-26), source + precompiled binaries, bindings for C/C++/C#/Java/JavaScript/MATLAB/Perl/PHP/Python/R/Ruby. Distribution model: linkable libraries (libSBML, libSEDML, libCombine, libcellml — licenses of the latter three unverified today) plus hosted community services (BioModels repository, BioSimulators/BioSimulations registry and runner). No copyleft obstacle to a Rust product reading/writing the formats; LGPL matters only if linking libSBML rather than reimplementing.

## adoption

Two-tier reality. SBML is the entrenched de facto standard: BioModels showed 1,096 manually curated + 1,682 non-curated + 833 auto-generated models today (biomodels.org, 2026-08-26); the ">230 supporting tools" figure is from a 2013 paper and no current count was verifiable (evidence-incomplete); MATLAB SimBiology and essentially every systems-biology tool import it; core spec last revised 2019 (L3V2 release 2019-03-29) — mature, slow-moving. libSBML shows modest visible GitHub activity (55 stars, 32 forks — much history predates GitHub). SED-ML is far weaker: the spec is actively maintained (L1V5 released 2024, published J Integr Bioinform) but BioSimulators' own documentation records that tools implement subsets, cannot execute archives with subdirectories, and emit SED-ML naming algorithms they did not use; a dedicated SED-ML Validator was needed just to debug interoperability. The decisive adoption datum: the BioModels reproducibility study (Mol Syst Biol 2021) found ~half of 455 published SBML-associated models could not be reproduced from the publication — the model format succeeded while the replay story failed. combine-specifications repo: 4 stars, 94 commits. CellML: alive (2.0.1, OpenCOR, Physiome Model Repository, 2026 governance board) but a much smaller community than SBML.

## lessons

Copy: (1) the OMEX shape — one archive = model + experiment description + data + typed manifest + metadata; ship it from day one rather than bolting the experiment format on a decade after the model format (SBML 2000 vs SED-ML 2011 is exactly the gap that produced the 50% irreproducibility number). (2) KiSAO's move: name algorithms and their parameters (tolerances) as ontology terms, so "which solver behavior" is a typed claim — extend it with implementation identity + exact version + hashes, which SED-ML lacks. (3) BioSimulators' conformance machinery: containerized backends behind one CLI, a test suite that measures what each tool actually supports, and per-capability registry entries — this is the orchestrator's admission gate. (4) SBML's numbered validation rules and level/version discipline with a semantic test suite. Mistake to avoid: advisory semantics. SBML made units optional and unit checks warnings so weak tools could still claim support; MIRIAM annotations are optional URIs; SED-ML conformance is voluntary. The result is a standard everyone "supports" and archives that don't replay — the strongest empirical argument that the product's fail-closed compile errors (units, vocabulary, assumptions) are the differentiator, provided it also avoids SBML's other trap: packages/features specified beyond what any implementation executes.

## cluster_answer

Fraction of the receipt story that already exists here: structurally about half, behaviorally much less. OMEX gives the container, per-file format typing, and RDF metadata; SED-ML gives model reference, declarative modifications, algorithm-by-ontology-term with tolerance/step parameters, tasks, and outputs. Missing from the specs: mandatory content hashes, solver implementation identity and exact version (KiSAO names the algorithm, not the binary), mandatory seeds, environment capture (BioSimulators' containers patch this outside the standard), and any standardized verdict/failure taxonomy — and tools have been documented emitting SED-ML that names algorithms they didn't use, so even the existing fields aren't trustworthy receipts. Units: advisory in practice and by design — SBML unit declarations are optional, the spec requires numeric self-consistency independent of units, and unit-consistency validation (105xx rules) yields warnings, not errors; real-world models routinely ship unit-inconsistent. SED-ML vs SBML adoption: SBML is universal in its niche (thousands of BioModels entries, broad tool support); SED-ML is the weak link — 13 years younger, implemented in inconsistent subsets (no repeated tasks, no archive subdirectories, XPath change support partial), needing a dedicated validator and the BioSimulators test suite to establish what "support" even means; the 2021 finding that ~50% of 455 published models were irreproducible is the measured consequence. Known limits: the RDF/MIRIAM annotation model is optional, unchecked, and link-rot-prone; there are no proofs or inference anywhere in the stack; versioning discipline is levels/versions with multi-year tool lag and draft packages stalled a decade; compliance is voluntary self-declaration. Net for the architect: not redundant — adopt the archive/manifest/ontology/conformance-suite patterns, but the fail-closed compiler, typed uncertainty, proof objects, and verdict taxonomy have no prior implementation here.

## largest_unverified_assumption

That SED-ML L1V5 still lacks mandatory fields for solver implementation identity/version, content hashes, and seeds — asserted from the spec's known structure and BioSimulators' compensating conventions, not from a line-by-line read of the L1V5 PDF during this task; if L1V5's KiSAO generalization actually added implementation-version or hash fields, the "half the receipt story exists" fraction understates the overlap.
