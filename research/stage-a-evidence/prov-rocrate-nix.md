## system

W3C PROV (PROV-DM/PROV-O), RO-Crate, WholeTale, and Nix/Guix — the four candidate provenance/reproducibility substrates for the proposed product's "receipts" layer

## overlap

Each subject covers one mechanism the proposed product's provenance/reproducibility-receipt bullet needs. PROV-DM (W3C Recommendation, 2013-04-30) is a domain-agnostic provenance data model: Entity/Activity/Agent nodes with typed relations (wasGeneratedBy, used, wasDerivedFrom, wasAttributedTo, wasAssociatedWith, actedOnBehalfOf), bundles for provenance-of-provenance, and a separate PROV-CONSTRAINTS validity spec; PROV-O is its OWL/RDF serialization. This is exactly the vocabulary a receipt would use to say "artifact X wasGeneratedBy solver-run Y using IR Z, attributed to solver S version V". RO-Crate standardizes the packaging: a directory (or archive) with a root `ro-crate-metadata.json` in schema.org-based JSON-LD describing a Root Data Entity, data entities, and contextual entities, with "profiles" specializing it for domains — the natural interchange envelope for a receipt plus its artifacts (source, IR, logs, outputs). WholeTale was the whole-product ambition as a hosted service: "tales" = executable research objects combining data references, code, computational environment, and narrative, republishable and re-executable — i.e., replay instructions as a first-class object. Nix and Guix supply the environment-pinning half of a receipt: a Nix derivation's store path hashes over the complete explicit input closure (name, all input deriving paths, outputs spec, system type, builder executable, args, environment variables), with fixed-output derivations pinning sources by content hash; `flake.lock` records per input the exact `rev` plus `narHash` (SHA-256 of the NAR serialization of the fetched tree), making evaluation and fetching reproducible across machines and time. Guix adds `guix describe` (channels file naming exact Guix commits) and `guix time-machine`, which re-runs any command under a historical Guix revision — demonstrated for multi-year environment reconstruction in a peer-reviewed Scientific Data paper. Together these cover the receipt fields "source/IR/artifact hashes, solver identities and exact versions, replay instructions" — as vocabulary (PROV), envelope (RO-Crate), platform precedent (WholeTale), and environment pin (Nix/Guix).

## insufficiency

Concrete missing mechanisms, per subject. PROV: no integrity layer at all — no canonical serialization for hashing, no signing, no tamper evidence, no identity binding; nothing makes a PROV graph TRUE (it is assertions, checkable only for internal consistency via PROV-CONSTRAINTS, not against what actually ran); no result taxonomy, no uncertainty representation, no notion of verdict or proof object. A receipts system needs provenance EMITTED by the compiler/orchestrator and cryptographically bound to artifacts; PROV only gives the graph shapes. RO-Crate: checksums are not core — the structure spec explicitly delegates inventories/integrity to optional complements (BagIt, OCFL); its own implementation notes say the BagIt SHA-512 manifest "does not provide proof the RO-Crate has not been deliberately tampered with" and offer only a detached-GPG-signature shell command as the tamper-evidence story; no signature format, no key/identity model, no verification procedure is standardized. No typed claims, no uncertainty, no verdicts. WholeTale: a grant-funded hosted multi-user platform, not a library; environment capture was container-based (image-level, not input-closure-level); and it is effectively dead (below), so it is precedent, not substrate. Nix/Guix: pin builds, not runs — nothing captures solver seeds, tolerances, convergence behavior, or outputs; input-addressed store paths guarantee the same recipe, not bit-identical outputs (bitwise reproducibility is a separate, incomplete property); no claim-level or artifact-level provenance vocabulary; Guix time-machine has a hard floor (v0.16.0, Dec 2018) and degrades with age (substitute availability, packages that no longer build); both are system package managers with daemons, not linkable Rust libraries. Nothing in the cluster distinguishes measurement/numerical/parameter/structural uncertainty, and nothing binds a logical verdict to the evidence that produced it.

## narrowing_history

Mixed across the cluster. PROV froze rather than narrowed: consolidated from the earlier Open Provenance Model lineage into the 2013 Recommendation, working group closed, no evolution since; companion specs (PROV-XML, PROV-AQ) stayed Notes and faded. RO-Crate IS a narrowing: the deliberately lightweight successor to the wf4ever Research Object/RO-Bundle ontology stack, keeping only schema.org-in-JSON-LD because researchers would not author heavyweight OWL (succession story evidence-incomplete this session; the lightweight design itself verified), now cautiously re-widening via profiles and a 2.0 effort. WholeTale stopped rather than narrowed: NSF grant OAC-1541450, main repo last push 2021-04-12, girder_wholetale archived (2024-06-24), dashboard.wholetale.org HTTP 404 on 2026-08-26 — the platform outlived neither its grant nor its own reproducibility horizon, while its homepage still advertises a running beta. Nix/Guix did not narrow; both expanded (flakes and lock files; Guix into HPC/scientific publishing via time-machine and Guix-HPC).

## adoption

PROV: 66 implementations were reported in the W3C implementation report at Recommendation time (2013-04-30, fetched). Thirteen years later it persists as the academic workflow-provenance vocabulary (e.g. CWLProv, and PROV mappings in workflow-run packaging profiles — evidence-incomplete, from background knowledge), but there is no mainstream software-industry uptake; the model is frozen. ## lessons

Copy: (1) PROV's three-node/typed-relation model as the receipt's export vocabulary — map receipts to PROV-O/RO-Crate at the boundary rather than inventing an incompatible graph, so receipts are consumable by existing tooling; keep the internal model typed and richer. (2) RO-Crate's pragmatism — a single well-known metadata file in a boring, hand-readable serialization beat the ontologically pure Research Object stack; the product's receipt format should be similarly boring and self-describing. (3) Nix's core idea — identity = hash of the complete explicit input closure of the recipe, with a lock file (rev + content hash per input) as the replay pin: a receipt should EMBED a flake.lock/`guix describe` channels file (or equivalent) rather than reimplement environment pinning, and record solver binaries by content hash so the environment claim is independently rebuildable, not just re-runnable. Avoid: WholeTale's mistake — coupling reproducibility to a hosted platform whose lifetime is a funding cycle; receipts must verify offline with a local library, with any hosted service strictly optional sugar. Also avoid PROV's mistake of standardizing assertions without integrity: a provenance record nobody can hash canonically or sign is testimony, not a receipt — the product must define canonical serialization + content addressing + signatures as core, day one, not an appendix.

## cluster_answer

Adopt vs build: ADOPT Nix (or Guix) as the environment-pinning substrate — record the lock/channels data and closure hashes inside your receipt instead of building a package manager; ADOPT PROV-O and RO-Crate as export/interchange mappings so receipts interoperate with archival tooling; BUILD the integrity and semantics layers yourself, because no subject provides them. What PROV standardizes: the provenance graph data model (Entity/Activity/Agent + seven core relations, bundles), an OWL vocabulary, a notation, and consistency constraints. What it leaves open: everything a receipt needs to be trustworthy — canonical bytes to hash, signing, tamper evidence, identity, and any binding between the asserted graph and what actually executed. What RO-Crate standardizes: package layout (`ro-crate-metadata.json` at root), schema.org-based JSON-LD description of a Root Data Entity plus data/contextual entities, and a profile mechanism. What it leaves open: integrity is explicitly delegated to optional wrappers — BagIt SHA-512 manifests for bit-rot, with the spec itself stating the manifest "does not provide proof the RO-Crate has not been deliberately tampered with", and tamper evidence reduced to an example detached GPG signature; no standardized signature format, key model, or verification procedure. What Nix/Guix pin that a container image digest does not: the RECIPE closure — every input by content hash (fixed-output source derivations, `flake.lock`'s rev+narHash per input), builder, arguments, environment, system type — so the environment is rebuildable from source and auditable input-by-input; Guix time-machine re-executes under an exact historical toolchain (back to v0.16.0, Dec 2018). A container digest pins only the built bytes: perfectly stable to run, opaque and unrebuildable (the Dockerfile's `apt-get` world has moved). Vice versa: the image digest guarantees byte-identical runtime anywhere with a container runtime, whereas Nix's input-addressed outputs are not guaranteed bit-identical on rebuild and replay depends on Nix being installed and substitutes/sources remaining fetchable. A receipt should carry both: the closure pin (auditability) and the artifact content hashes (byte identity). Adoption reality: PROV frozen-but-persistent in academic provenance; RO-Crate small, active, releasing (1.3.0 in June 2026); WholeTale dead (dashboard 404, repos dormant/archived); Nix large and very active; Guix smaller, active, with peer-reviewed scientific-reproducibility credentials.
