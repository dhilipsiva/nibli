## subject

Context/claim formalisms — design inputs for the fail-closed deterministic lifting mechanism, the 17-claim-kind schema, supersession semantics, and declared conflict-resolution policies (Stage B)

## findings

CONTEXT LOGIC. McCarthy's ist(c,p) (IJCAI-93, fetched and text-extracted) asserts "the proposition p is true in the context c," with contexts as first-class objects. Three formal properties matter for our design. (1) Lifting axioms are relation-and-context-specific formulas stated in an outer context: his §4 example lifts a static blocks theory (on(x,y) in above-theory) into a context c where "on and above have a third argument denoting a situation" — i.e., the canonical lift is a SIGNATURE-CHANGING transform (argument extension), not mere copying. (2) Entering/exiting contexts are natural-deduction assumption and discharge: "the operation of entering c [is] analogous to assuming c"; having derived q inside, "one can leave c and get ist(c,q)". (3) There is no free lunch at the top: sentences are always themselves in a context (ist(c0, ist(c1,p))); "transcending the outermost context seems to require a changed logic with... reflexion principles," and relative decontextualization is only "relatively eternal" — a common context above the ones in play. McCarthy explicitly notes that which logic licenses his lifting derivation (substitution of sentences for variables) was unsettled — quasi-quotation, Buvač–Mason, etc., "all have disadvantages." Guha's 1991 thesis (STAN-CS-91-1399; seen via secondary abstracts) supplies the microtheory mechanics: each microtheory = axioms + a vocabulary, "interrelated through lifting rules stated in an outer context," and (Guha & McCarthy 2003) different context varieties (projection, approximation, ambiguity, mental-state) need DIFFERENT KINDS of lifting rules. The Cyc production version (already evidenced locally) ran lifting under defeasible argumentation, which destroyed auditability. The deterministic fail-closed rendering that survives all of this: replace lifting AXIOMS (arbitrary formulas, undecidable to check) with lifting DECLARATIONS — a closed, typed catalog of transforms attached to explicit per-relation import statements, plus one implicit case (unchanged inheritance down a declared specialization DAG, Cyc's genlMt behavior). What makes a lift compile-time checkable is that every ingredient is static: the context partial order is declared and acyclic; each context's assumptions are a typed record (A.5.5); each transform is a total (or explicitly partial-with-domain) function on the claim's type; regime predicates evaluate over the target context record with the A.5.4 three-outcome rule. A lift becomes typed function application — no search, no defaults. The failed lift is then a structured, blameable artifact: it names the claim version, source/target context versions, the lifting declaration considered (or its absence), and the exact assumption or regime variable that failed with required-vs-actual values; this record IS the out_of_regime payload. McCarthy's enter/exit maps onto the product cleanly: query = enter exactly one assembled context; every verdict is exported only as context-scoped (discharge), and "relative decontextualization" (an automatic most-general context) is deliberately absent.

CLAIM-TYPING PRECEDENTS. Nanopublications (nanopub.net + working-draft guidelines, fetched): a nanopub is four named graphs — head, assertion ("the main claim"), provenance ("information about the assertion"), publication info (attribution+timestamp) — with genuinely normative MUSTs ("A nanopublication MUST comply with all of the following criteria to be considered well-formed"; all triples in exactly one graph; provenance must reference the assertion). Crucially, the MUSTs are STRUCTURAL (graph well-formedness), not domain-field-level: nothing forces a measurement to carry an uncertainty. Immutability is delivered by Trusty URIs (content-hash identifiers). Adoption honestly: >10 million nanopubs on an 11-server network (Kuhn et al. 2021), but the bulk are batch conversions of databases; the same paper's authoring study yielded 42 users and 81 non-introduction nanopubs — an interchange format, not an authoring ecosystem. Micropublications (Clark/Ciccarese/Goble 2014, fetched): claims + support/challenge DAGs down to data and methods; "the minimal micropublication is a statement with its attribution" — i.e., mandatory-ness is deliberately MINIMAL to buy incremental adoption; their critique of nanopubs (no claim networks of arbitrary depth, no transitive closure to empirical evidence) is exactly the requirement our evidence graph already carries. Domeo, its tool, is defunct. SEPIO (Monarch GitHub, fetched): Assertion / Evidence Line / Evidence Item trisection; repo carries a warning that the OWL ontology "is out of date with the most recent developments in the SEPIO Model" — the effort moved into LinkML/JSON-Schema form inside GA4GH VA-Spec. That successor is the ONE fetched precedent with machine-enforced field-level mandatory-ness: VA-Spec's Statement requires type, proposition, direction at cardinality 1..1 via JSON Schema — but only three fields; everything else (strength, classification, evidence lines) is optional. OBI: OWL class definitions for >2500 assay/device/objective terms; open-world OWL cannot make a missing field an error — the community's actual mandatory-ness lived in minimal-information checklists enforced editorially. PROV-O (W3C REC 2013-04-30): the qualified pattern ("restates an unqualified influence relation by using an intermediate class") is the stable way to attach roles, activities, and times to derivation edges; prov:wasRevisionOf specializes wasDerivedFrom; prov:wasInvalidatedBy/invalidatedAtTime bound an entity's validity period. Net answer to the brief's question: NO precedent enforces kind-mandatory fields at our breadth; VA-Spec proves the enforcement mechanism (schema-required fields per statement type) at small scale, and everyone else substituted structural well-formedness (nanopub), minimalism (micropub), or documentation (OBI/MIBBI).

VERSIONING/SUPERSESSION. Shipped practice converges on immutable-plus-edge: nanopubs "can never [be] edit[ed] nor delete[d]"; npx:supersedes points new→old in the pubinfo graph; npx:retracts is a separate nanopub, valid only "signed with the same public key as the nanopublication that it retracts" (authority-bound); query services implement get_latest_version by following the chain. OBO: "IDs are never deleted or reused"; owl:deprecated + OBSOLETE label + IAO:0100001 term-replaced-by + coded obsolescence reasons (IAO:0000226/227). Wikidata ranks: deprecated statements stay queryable and citable, with P2241 reason-for-deprecated and P7452 reason-for-preferred qualifiers; "truthy" computation = best-rank-wins. None of these auto-recompute downstream conclusions; staleness surfaces at read/query time. That matches A.5.3's context-pinning: a verdict is valid FOR its pinned context version forever; supersession changes what the NEXT context version assembles.

CONFLICT POLICIES. Bleiholder & Naumann (VLDB'09 tutorial, text-extracted) is the standard taxonomy: conflict-ignoring / conflict-avoiding ("a single decision is made, e.g., preference of a source, and applied to all conflicts") / conflict-resolving, the last split instance-based vs metadata-based and deciding ("choose a preferred value among the existing values") vs mediating ("produce an entirely new value, such as the average"). Named strategies: Trust-your-friends (preferred source), Keep-up-to-date (most recent), Cry-with-the-wolves (most frequent), Roll-the-dice, Meet-in-the-middle. Shipped recorded adjudication at scale exists only in Wikidata's manual rank system; declared AUTOMATIC policies with receipts are research prototypes — so our receipt-recorded policy application is a genuine (small) novelty, and the v1 policy set should be exactly the Stage A three, all "deciding" strategies; "mediating" strategies fabricate unsourced values and must be banned.

## design_recommendations

- **decision**: Lifting-rule language | **recommendation**: Replace lifting AXIOMS with lifting DECLARATIONS: a context declares, per relation, `import R from C via T` where T comes from a closed typed transform catalog — v1 catalog: identity (signature-preserving copy), argument-extension (add a declared context parameter with a fixed binding, McCarthy's on(x,y)→on(x,y,s) with s bound), parameter-specialization (bind a source context variable to the target's narrower value), and unit/frame recontextualization (delegated to the quantity type system). No user-defined transform functions in v1. | **rationale**: Arbitrary lifting axioms are formulas whose soundness is undecidable to check and whose interaction made Cyc's cross-context outcomes unauditable; McCarthy himself never settled which logic licenses his lifting derivations. A closed catalog makes every lift a typed function application, checkable and deterministic, and covers the lifts the four domains actually need (regime narrowing, condition binding, frame/unit moves). | **alternatives_rejected**: General context-morphism functions (user-supplied T): expressive but reintroduces unverifiable code at the soundness boundary — defer to v2 behind a certificate obligation. Arbitrary ist-style lifting axioms: Cyc's path, rejected per the standing owner ruling. Inheritance-only (no transforms): fails Gate 1 — McCarthy's canonical example already requires a signature change.
- **decision**: Implicit lifting scope | **recommendation**: Exactly one implicit lift: unchanged inheritance downward along a declared specialization partial order (child context sees parent assertions), required to be a DAG, signature-preserving, and assumption-monotone (child's typed assumption record must refine the parent's — checked at declaration time). Everything cross-branch or signature-changing needs an explicit import declaration. | **rationale**: This is Cyc's genlMt behavior — the one lifting mode that ran deterministically for decades — and it is compile-time checkable as a subtyping check on context records. Making it the only implicit mode keeps 'where did this claim come from' answerable by a single declared path. | **alternatives_rejected**: No implicit lifting at all: forces thousands of identity imports, punishing the common case and inviting macro escape hatches. Multiple-inheritance with automatic context intersection (Cyc's IntersectContexts): reintroduces ambiguity about which assumptions govern; context composition in v1 must be an explicit new context declaration listing its imports.
- **decision**: Static checkability conditions for a lift | **recommendation**: A lift compiles iff three statically evaluable conditions hold: (1) assumption compatibility — every assumption variable of the source context is either preserved, or explicitly rebound by the transform, judged over the typed context records of A.5.5; (2) transform totality — T is total on the claim's type, or carries an explicit domain-of-definition that the compiler discharges against the claim's declared regime (typed partiality per amended Gate 1); (3) target regime satisfaction — the target context record satisfies the claim's regime predicates (A.5.4 three-outcome rule). No runtime search, no defaulting. | **rationale**: Each condition is a record comparison or predicate evaluation over declared, versioned data — this is what 'deterministic fail-closed lifting' cashes out to, and it is exactly the part Cyc left to defeasible argumentation and McCarthy left to future logic. | **alternatives_rejected**: Proof-search over lifting axioms at query time (undecidable/nondeterministic); trusting the author's assertion that a lift is sound (fails the fail-closed rule — conventions enforced by documentation are Gate 1 failures).
- **decision**: Failed-lift error payload (the out_of_regime record) | **recommendation**: A failed lift emits a structured record: {claim_id+version, source_context id+version, target_context id+version, candidate lift paths considered (each: declaration id or 'specialization-DAG' or 'none declared'), per-path failure ∈ {no_lift_declared, assumption_violated{var, required, actual}, transform_partial{domain_condition, violating_value}, regime_violated{predicate, actual}}, and the distinguished case regime_undeterminable{missing_var} which routes to invalid_input, not out_of_regime, per A.5.4}. The verdict renderer prints the first-failing variable with required-vs-actual. | **rationale**: out_of_regime is only useful if it names what to fix; enumerating every candidate path prevents the 'silently took the wrong path' ambiguity, and separating missing-context (author's fault, invalid_input) from excluded-regime (world's answer, out_of_regime) keeps the two-axis taxonomy honest — this mirrors SZS's success/no-success discipline already adopted in A.4. | **alternatives_rejected**: A bare out_of_regime enum with prose message (unauditable, unmechanizable); collapsing missing-variable into out_of_regime (would let authors read 'model excluded' when they merely failed to declare, the ideal-gas-guess failure A.5.4 exists to prevent).
- **decision**: Claim-kind mandatory-field enforcement mechanism | **recommendation**: Enforce the 17 kinds' mandatory fields as schema-required fields in the surface language's typed claim constructors (the VA-Spec JSON-Schema 'required' mechanism, generalized), compiled and validated in the same fail-closed pass as units and names. Adopt nanopublication's trisection as the claim RECORD LAYOUT — every claim = {assertion, provenance, publication-info} sections with kind-specific required fields inside each — but as native typed records, not RDF named graphs. | **rationale**: Survey answer: no precedent enforces field-level mandatory-ness at this breadth; GA4GH VA-Spec is the one fetched system that machine-enforces required fields per statement kind (type/proposition/direction at 1..1), proving the mechanism; nanopub's MUSTs proved structural well-formedness is checkable; OBI/OBO's OWL open-world provably cannot make a missing field an error. So: take VA-Spec's mechanism, nanopub's shape, and our breadth. | **alternatives_rejected**: OWL/ontology-based claim modeling (open-world semantics cannot fail closed on absence); micropublication-style minimalism (claim+attribution only — their adoption strategy, but it is precisely the fail-open convention the product exists to refuse); RDF named-graph implementation (drags in triple-store machinery; the trisection is the valuable part, not the serialization).
- **decision**: Precedent verdicts (adopt / adopt-the-shape / avoid) | **recommendation**: Nanopublications: ADOPT-THE-SHAPE (trisection, immutability via content-hash identity, authority-bound supersession/retraction predicates); AVOID the RDF/named-graph stack and the decentralized-network layer. Micropublications: ADOPT-THE-SHAPE (support/challenge edges typed in the evidence graph, transitive closure of claims to evidence); AVOID the full argumentation semantics (defeasible warrant is the Cyc failure mode again; tooling is dead). SEPIO: ADOPT-THE-SHAPE (Assertion/EvidenceLine/EvidenceItem as the evidence-graph edge typing); AVOID the OWL artifact (self-declared out of date; its own authors moved to LinkML — schema languages beat ontologies for this job). OBI: use as transcription SOURCE for assay vocabulary under the transcription-only governance rule; not a claim schema. PROV-O qualified patterns: ADOPT for receipt provenance (qualifiedDerivation with activity+usage; wasRevisionOf for supersession edges' interchange rendering) — it is a stable 2013 W3C REC and costs nothing at export time. | **rationale**: Each verdict traces to a fetched property: nanopub's normative MUSTs and >10M-but-batch adoption; micropub's minimal-mandatory design and defunct tooling; SEPIO's own out-of-date warning and VA-Spec succession; PROV-O's REC status. | **alternatives_rejected**: Adopting any of them wholesale as the claim model (none enforces our mandatory-ness or typed quantities); inventing an interchange vocabulary where PROV/nanopub terms exist (violates transcription-only spirit at the interchange seam).
- **decision**: Supersession semantics | **recommendation**: Claims immutable; two distinct edge kinds, both authority-bound to the original claim's owner key (nanopub precedent): supersedes(new→old, reason_code) and retracts(old, reason_code) with no successor. Reason codes are a closed enum seeded from IAO obsolescence codes (error, merged, better-method, superseded-measurement...). Verdict records already pin basis claim versions (A.5.3): on supersession, NOTHING recomputes automatically; a verdict re-read against 'latest' context resolves the chain (nanopub get_latest_version pattern), and the read layer computes annotations: stale_basis (a basis claim has a successor) vs basis_retracted (a basis claim was withdrawn). basis_retracted verdicts are barred from being cited as basis in NEW derivations until re-evaluated; stale_basis verdicts remain citable with the flag. Cache invalidation stays keyed on pinned context content (Stage D), so 'latest'-mode caches invalidate, pinned-mode caches do not. | **rationale**: Every shipped system (nanopub, OBO, Wikidata) keeps superseded content queryable and pushes staleness to read time; auto-recomputation on every upstream edit is unbounded work and destroys the reproducibility property that a receipt describes exactly what was true of its pinned inputs. Retraction must be stronger than supersession because there is no successor to re-resolve to. | **alternatives_rejected**: Eager cache-invalidation-and-recompute on supersession (unbounded, and silently changes answers under users — the false-green class); doing nothing at all (a retracted-basis verdict circulating unflagged is the semantic-publishing failure the retraction literature documents); mutable claims with version history (loses content-hash identity and the signature-binding trick).
- **decision**: v1 conflict-resolution policy set and receipts | **recommendation**: Ship exactly three declared policies — prefer_newer, prefer_source_rank(total_order), manual(claim_id) — all classified 'deciding' in Bleiholder–Naumann terms (prefer_newer = Keep-up-to-date; prefer_source_rank = Trust-your-friends; manual = human decision reified as a claim). Ban 'mediating' strategies (Meet-in-the-middle averaging) and frequency voting (Cry-with-the-wolves) in v1. Policies must be total over the conflict set or fail closed: prefer_source_rank over sources absent from the declared order, and prefer_newer over ties/missing dates, return conflicting — never guess. The receipt records: policy id+version, conflict set (all claim ids+versions), winner, and per-loser exclusion reason — the Wikidata reason-qualifier pattern (P7452/P2241) generalized to automatic application. | **rationale**: Deciding strategies always output a SOURCED value, preserving zero-fabrication; averaging fabricates an unattributable number and voting rewards copy-count (the data-fusion literature's known copying pathology). Wikidata is the only at-scale precedent for recorded adjudication and it records reasons — but its application is manual curation, so receipt-recorded automatic policy application is our (small) novelty and must stay total and deterministic. | **alternatives_rejected**: Truth-discovery/source-reliability learning (probabilistic, nondeterministic across runs, unauditable); mediating fusion functions (unsourced values); a default policy when none is declared (A.5.2 already rules: no policy ⇒ conflicting).
- **decision**: Query discipline from enter/exit; no outermost context | **recommendation**: Formalize A.5.2's assembled-context rule as McCarthy's enter/discharge: a query enters exactly one assembled context; all internal inference is classical within it; every exported result is context-stamped (the discharge ist(c,q)) — there is no context-free verdict type in the IR, no automatic 'relative decontextualization', and no outermost context. Cross-context comparison of the same proposition (structural uncertainty) is a first-class query FORM (evaluate under c1, c2, ... and tabulate), never a merge. | **rationale**: McCarthy's own analysis: transcending the outermost context requires reflection principles beyond FOL, and decontextualized sentences are only 'relatively eternal' — a context-free verdict type would be a standing invitation to lift-by-accident. The stamped form also makes the evidence-graph/assembled-context split visible in every result. | **alternatives_rejected**: A distinguished root context holding 'universal' claims (becomes a dumping ground whose assumptions are never checked — the failure McCarthy's c0 regress warns about); allowing multi-context queries with implicit union (reintroduces exactly the inconsistency the assembly check exists to refuse).
- **decision**: Lifting declarations are versioned, owned content | **recommendation**: Treat every import declaration and every specialization edge as a claim-like artifact: versioned, owner-only on the IMPORTING context (you may import from anyone; only the context owner declares its imports), cited in the basis of any verdict that used the lifted claim, and subject to supersession like any claim. A changed lift is a new context version. | **rationale**: Symmetry with A.5.6's closure rules — a lift, like a closure, silently widens or narrows what a context can conclude, so it needs the same authority + visibility defence; and it makes the out_of_regime payload's 'declaration considered' field a stable citable id. | **alternatives_rejected**: Lifts as unversioned configuration (invisible basis changes — the false-green class again); bilateral lifts requiring the source owner's consent (source owners cannot foresee importers; the import direction carries the risk and hence the authority).

## adopt

Nanopublication trisection as claim record layout + Trusty-URI-style content-hash claim identity + authority-bound supersedes/retracts edge pair (nanopub guidelines working draft + nanopub-py docs, accessed 2026-08-26); GA4GH VA-Spec's schema-required-fields mechanism (va-spec.ga4gh.org, latest docs 2026-08-26) generalized to all 17 kinds; SEPIO's Assertion/EvidenceLine/EvidenceItem edge typing in its post-OWL LinkML incarnation, not sepio.owl; W3C PROV-O REC (2013-04-30) qualified patterns + prov:wasRevisionOf/wasInvalidatedBy for receipt interchange; IAO obsolescence reason codes (IAO:0100001, IAO:0000226/227) as the seed enum for supersession/retraction reasons; OBO's ids-never-deleted-or-reused rule and ISO-8601-dated immutable version IRIs (OBO Foundry FP-004); Bleiholder–Naumann strategy taxonomy as the classification vocabulary for policies (deciding/metadata-based only); Wikidata's reason-qualifier pattern (P7452/P2241) for recording why a claim won/lost adjudication; McCarthy's enter/discharge as the formal reading of assembled-context queries, with context-stamped verdicts (ist(c,q)) as the only result form.

## avoid

Arbitrary lifting axioms or defeasible cross-context argumentation (Cyc: made lifting unauditable; McCarthy never settled the licensing logic — causes silent unsound imports); OWL/open-world encodings of claim schemas (cannot fail closed on a missing field — OBI/SEPIO evidence; SEPIO's own repo declares the OWL artifact out of date); RDF named-graph implementation of the trisection (machinery cost without the enforcement benefit); micropublication-grade minimal mandatory-ness (claim+attribution only — deliberately fail-open for adoption, the opposite bet); mediating fusion strategies (averaging fabricates unsourced values) and frequency voting (rewards copy-count) in conflict resolution; automatic recomputation of downstream verdicts on supersession (unbounded, silently changes answers; every shipped system resolves staleness at read time instead); a context-free verdict type or root 'universal' context (McCarthy: outermost-context transcendence needs reflection principles; a root context becomes an unchecked dumping ground); nondeterministic truth-discovery/source-trust learning as a resolution policy (unauditable, run-dependent).

## open_questions

- The v1 transform catalog (identity, argument-extension, parameter-specialization, unit/frame move) is hypothesized sufficient for the chemistry+biology vertical — Stage B fidelity testing must try to break it with real cross-context lifts (in-vitro→in-vivo, dilute→concentrated, per-organism parameter binding) before freezing it.
- Whether assumption-monotonicity down the specialization DAG should be structural subtyping on context records or nominal (declared refines-edges only) — structural is more automatic, nominal is more auditable.
- Whether stale_basis should be computed eagerly (graph walk at supersession time, materialized flag) or lazily at read — read-time is recommended here but the cost model belongs to Stage D caching.
- Guha's thesis itself (STAN-CS-91-1399) was only reachable via secondary abstracts; if Stage B wants his exact lifting-rule syntax for the four context varieties, the thesis PDF needs to be sourced.
- prefer_newer needs a defined timestamp: publication date, retrieval date, or measurement date differ per claim kind — which field the policy reads must be fixed per kind or the policy is ambiguous.
- Whether a retraction may itself be retracted (nanopub practice is silent; Wikidata allows rank changes both ways) — recommend no in v1, but it needs an explicit ruling.
- How lifting declarations interact with closure (A.5.6): does importing a closed relation import its closure? Recommended default: no — closure never lifts — but this needs its own Stage B decision row.
