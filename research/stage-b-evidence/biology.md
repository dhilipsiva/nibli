## subject

Biology domain IR requirements (Stage B design inputs, prompt §7): coordinates, identifier stability, entity typing, defeasible biological generalizations, large-artifact externalization

## findings

**Coordinates and identity: the GA4GH digest stack is decided infrastructure, not a candidate.** VRS 2.0 and refget Sequence Collections (seqcol) were approved by the GA4GH Product Steering Committee on 2025-03-27; current VRS stable is 2.0.1. All three layers share one digest convention: SHA-512 truncated to the left-most 24 bytes (192 bits), base64url-encoded (RFC 4648), yielding identifiers `ga4gh:<type>.<digest>` with type prefixes VA (Allele), SL (SequenceLocation), SQ (sequence/refget), CN/CX (copy number), AJ/TM/DM (structural), CPB (CisPhasedBlock — VRS 2.0's rename of Haplotype). refget Sequences v2.0.0 canonicalizes a sequence (strip non-alphabetic, uppercase, A–Z alphabet) before digesting, so sequence identity is content identity, independent of any accession authority. seqcol extends this to collections: RFC 8785 JSON canonicalization of collated `names`/`lengths`/`sequences` arrays, per-attribute GA4GH digests, then a top-level digest; only names and sequences are *inherent* (identity-bearing) by default, and a `/comparison` API answers "can these two reference sets be jointly analyzed" — precisely the compile-time compatibility check the product needs before accepting two coordinate-bearing claims into one context. VRS explicitly designs its computed identifiers to "obviate centralized registration services" and guarantee identical objects ⇒ identical identifiers — deterministic, offline-computable, exactly matching the product's deterministic-compilation contract. VRS SequenceLocation is 0-based inter-residue (interbase), `start ≤ end`, over a `sequenceReference`; the fetched field summary shows no strand field (variation is expressed in the reference sequence's own orientation), so strand is a property of *features*, not of VRS alleles — the coordinate type must reconcile this (see recommendations).

**Accession versioning is uniform enough to legislate on.** NCBI assemblies: `GCA_ddddddddd.v` (GenBank archival submission) vs `GCF_ddddddddd.v` (NCBI's RefSeq derivative), versioned independently (GCA_009914755.4 pairs with GCF_009914755.1); versions increment on sequence change, and since 2024 also on sequence *renaming*. RefSeq records: `accession.version` increments iff sequence data changes; annotation-only updates leave the version untouched — so a pinned accession.version fixes the residue string but *not* the annotation, which matters for feature claims. Ensembl stable IDs (`ENS[species][type][number].version`): version increments on sequence/exon-coordinate/splicing changes; IDs are retired and reissued on drastic model changes. HGNC: symbols are updated "only in exceptional circumstances," a "stable" tag marks reviewed-final symbols (3,581 genes as of the 2026 NAR paper), and HGNC's own position is that the HGNC ID (`HGNC:#`) "stays the same even if the nomenclature is updated" — the authority itself tells you not to key on symbols. NCBI Taxonomy ships its instability as data: `merged.dmp` (old taxid → current taxid) and `delnodes.dmp` (dead taxids) in every taxdump release, so a compiler can mechanically classify any taxid as current/merged/deleted against a pinned release. Cellosaurus assigns `CVCL_xxxx` accessions (identical to RRIDs) to >144k cell lines and, with ICLAC, maintains the problematic/misidentified list (~8.6% of cell lines in the literature are on it; papers using RRIDs drop to 3.3%) — cell-line identity is a solved-by-accession problem the product should import wholesale.

**Entity typing.** The gene/product conflation has a standards-level answer: HGNC/Ensembl gene IDs name the *locus*, RefSeq NM_/NP_ and Ensembl ENST/ENSP name *products*, refget SQ digests name *strings*, and the Sequence Ontology is already the mandatory controlled vocabulary for feature kinds (GFF3 column 3 "is constrained to be either a term from the Sequence Ontology or an SO accession number," with parent/child type-hierarchy validation). So the IR does not invent a type lattice; it transcribes one: Sequence (digest), Feature (SO-typed region on a sequence), Gene (locus), Transcript, Protein as distinct nominal types with typed `product_of`/`located_on` edges, and *no implicit coercion* between them — "TP53 inhibits MDM2" must fail closed until the author says which entity kind each name denotes. Assay/protocol context: OBI is a full-membership OBO Foundry ontology covering investigation design, protocols, instruments, materials, and analyses; BAO is the screening-assay-specific complement ("different, but not incompatible approaches"). GO annotation practice supplies two mechanisms the rule design should copy: every annotation carries an evidence code and a reference (PMID/DOI/GO_REF), and the NOT qualifier records *curated exceptions* ("does NOT enable…"), applied only on positive evidence of absence — exceptions as data, not as inference.

**Defeasible biological generalizations.** The Cyc evidence file (read in full) supplies both the mechanism and the correction: microtheories scope assertion bundles under factored-out domain assumptions, with explicit lifting rules; Cyc's fatal choice was making the *substrate* default-true ("even deduction in Cyc is not sound"), which cost soundness, determinism, and checkable proofs. Stage A already rules: no paraconsistency, classical logic inside assembled contexts, `out_of_regime` = failed lift, closure owner-only and cited (A.5.2/A.5.6), and validity regimes as typed predicates with fail-closed undeterminable-context (A.5.4). The biology answer follows: biological generalizations are *never* bare universals; they are either context-scoped defaults with declared exception classes (compiling, inside an assembled context, to classical guarded implications whose exception relation is open-world unless owner-closed — verdicts capped at `supported` when the guard is unclosed) or statistical claims bound to a reference population (a distinct A.5.1 claim kind). An unscoped `∀x: Human(x) → …` over an empirical relation is a compile error naming the three repairs. This keeps the core monotonic and classical — the anti-Cyc invariant — while making the exception structure of biology first-class instead of a documentation convention (which would fail the Gate 1 fidelity test).

**Large artifacts.** The BioModels post-mortem in the local evidence file is the governing precedent: references that were names, not content hashes, produced dangling files, NaN parameters, and stale URLs inside even the *curated* corpus, with a 2025 repair campaign and only 88% end-to-end reproducibility. The mechanism is therefore content addressing with typed metadata: refget/seqcol digests for sequences and reference sets (already the GA4GH convention), and a generic `ExternalArtifact` type (media type + declared schema + digest + size + retrieval hint) for alignments, images, and datasets. The threshold is *semantic*, not byte-count-first: whatever appears as a term in logical claims stays in the KB; whatever inference treats as opaque goes external — with a small inline allowance for short sequence literals (still digested) purely for authoring ergonomics.

Version/date discipline: every normative claim above was verified against a fetched source dated 2026-08-26 except where key_facts tags say otherwise (VRS strand-absence is an inference from the fetched field list; the seqcol approval search summary said 2025-01-06 but the fetched GA4GH announcement says 2025-03-27 — the fetched page governs; HPO/MONDO/UBERON/PSI-MI suitability was not fetched this task).

## design_recommendations

- **decision**: Sequence and variant identity: adopt GA4GH computed identifiers outright, computed in-house | **recommendation**: Make refget ga4gh digests (SQ.<base64url(sha512/24B)> over the canonicalized uppercase sequence) the native identity of Sequence; seqcol top-level digests (RFC 8785 canonicalization, inherent attributes names+sequences) the native identity of assemblies/reference sets; and VRS 2.0 computed identifiers (ga4gh:VA./SL./CPB./CN./CX. …) the native identity of variants and locations. The compiler implements the digest algorithms itself (they are public, deterministic, offline) and, when a user supplies a ga4gh CURIE, recomputes and verifies it — a mismatch is a compile error, not a warning. | **rationale**: Identical objects ⇒ identical identifiers with no registration authority is exactly the product's deterministic-compilation and hash-bound-receipt contract, already ratified by GA4GH (VRS 2.0 + seqcol approved 2025-03-27; VRS stable 2.0.1). Transcription-only governance is satisfied: the algorithm, prefixes, and normalization are all normatively specified. | **alternatives_rejected**: HGVS strings as identity (non-canonical, parse-ambiguous, multiple spellings per variant); dbSNP rsIDs (central authority, merge churn, no content binding); an in-house hash scheme (breaks federation with ClinVar/VICC-style consumers and violates transcription-only governance for zero benefit).
- **decision**: The concrete genomic coordinate type and its fail-closed errors | **recommendation**: One canonical IR type: GenomicInterval { reference: SequenceRef, start: u64, end: u64, strand: Strand } where SequenceRef is a refget SQ digest or a seqcol member (a versioned GCA_/GCF_ accession is accepted at the surface and resolved to its seqcol/SQ digest at compile, with the resolution in the receipt); start/end are interbase 0-based half-open with start ≤ end (the VRS convention); Strand = Plus | Minus | Unstranded, where Unstranded must be written, never defaulted. Surface syntax accepts 1-based fully-closed input only under an explicit annotation (e.g. coords: one_based_inclusive), converted deterministically at compile; the receipt records both spellings. Fail-closed errors, one per missing component: E_BIO_NO_REFERENCE (no assembly/sequence named — 'chr7:117559590' alone never compiles), E_BIO_UNVERSIONED_REFERENCE (GCF_000001405 without .vN), E_BIO_NO_COORD_CONVENTION (numbers given without declaring the base/openness convention), E_BIO_NO_STRAND (a feature kind whose SO type is stranded, with strand omitted). Variant Alleles are the one strand-free case, by construction: they adopt VRS SequenceLocation verbatim, expressed in the reference sequence's own orientation. | **rationale**: Interbase-internal kills the entire off-by-one class at one seam; making the convention an explicit surface annotation rather than a default is the fail-closed doctrine applied to biology's best-known silent corruption (BED vs VCF vs GFF conventions). Assembly-in-the-type is Stage A A.5.5's own canonical example, now made concrete. | **alternatives_rejected**: 1-based-inclusive internal representation (matches HGVS/GFF3 habit but VRS, BED, and the digest stack are interbase — conversion would then live at the identity-critical seam); strand on every coordinate including variants (contradicts VRS 2.x, whose SequenceLocation carries no strand field); accepting convention-less coordinates with a documented default (a documentation-enforced convention is a named Gate 1 failure).
- **decision**: Identifier instability policy: pin versioned accessions in the IR; resolve symbols at compile time under a pinned nomenclature snapshot, recorded in the receipt | **recommendation**: Adopt the middle option, made safe by pinning. (1) The IR and evidence graph store only version-fixed, digest-anchorable identifiers: RefSeq accession.version, Ensembl stable-ID.version, GCA_/GCF_ with version, HGNC:#, NCBITaxon current taxid + taxdump release, CVCL_xxxx + Cellosaurus release. (2) The surface language accepts human symbols (TP53, BRCA1) only when the document imports a named nomenclature snapshot (HGNC dataset release, pinned by date + digest); compilation resolves symbol → HGNC:# → the author-selected product accession, records the full chain in the receipt, and errors on any symbol that is withdrawn, an alias of multiple IDs, or absent from the pinned release — listing candidates in the error. (3) Bare unversioned accessions are always E_BIO_UNVERSIONED_REFERENCE. Authoring-ergonomics cost, stated: every document carries one snapshot-import line, and authors occasionally hit resolution errors on symbols they consider unambiguous; the mitigation is that the error message contains the exact pinned-ID repair, and the snapshot line is shared per project, not per claim. | **rationale**: HGNC itself says symbols change (if only 'in exceptional circumstances') while HGNC IDs never do — so symbols are surface sugar, IDs are identity; this is the authority's own guidance transcribed. Refusing symbols entirely would make the product unusable for its Meera persona (biologists author in symbols — the SEPT2/Excel literature exists because of it), while accepting symbols as identity reproduces exactly that failure inside the KB. | **alternatives_rejected**: Refuse bare symbols outright (maximal safety, but the resolution step is deterministic under a pinned snapshot, so refusal buys no soundness — only friction); resolve symbols against a live service at compile time (nondeterministic compilation, network in the TCB); store symbols and resolve at query time (the same claim silently changes meaning across nomenclature releases).
- **decision**: Taxonomy, strains, and cell lines: pinned taxdump semantics; cell lines are not organisms | **recommendation**: Compile taxids against a pinned NCBI taxdump release. A taxid found in merged.dmp is automatically rewritten to the current taxid with the rewrite recorded in the receipt (it is the authority's own equivalence assertion); a taxid in delnodes.dmp is a hard compile error; strains use NCBI strain-level taxids where they exist, otherwise a distinct Strain entity keyed to a culture-collection accession. CellLine is a separate nominal type keyed by Cellosaurus CVCL accession (= RRID) + pinned Cellosaurus release; it is never a subtype of Organism (it carries species-of-origin as a typed edge). A measurement claim whose specimen CVCL is on the Cellosaurus/ICLAC problematic list at the pinned release compiles, but the problematic status enters the claim's context record and every dependent verdict's basis — the A.5.6 visibility pattern applied to specimen identity. | **rationale**: NCBI ships merged/deleted status as machine-readable data, so current/merged/deleted classification has a mechanizable oracle — the transcription-only criterion met exactly. Cell-line misidentification (~8.6% of literature lines problematic; RRID use measurably reduces it) is the largest known silent-context failure in experimental biology; surfacing it in the basis rather than refusing keeps the product a recorder of attributed claims per A.5.2. | **alternatives_rejected**: Refusing merged taxids (punishes authors for the authority's own housekeeping); treating cell lines as organisms of their source species (HeLa-as-Homo-sapiens is the exact conflation the type system exists to prevent); hard-refusing problematic cell lines (the evidence graph must be able to record claims about contested material — the verdict layer, not ingest, is where it bites).
- **decision**: Central-dogma entity lattice: five distinct nominal types with no implicit coercion; SO as the mandatory feature-kind vocabulary | **recommendation**: Distinct types: Sequence (refget digest; a string, nothing more), Feature (an SO-typed region: GenomicInterval + SO term, mandatory), Gene (locus entity: HGNC:# or Ensembl gene ID; has no sequence, no coordinates of its own — it has features and products via typed edges), Transcript (ENST/NM_ .version; product_of Gene), Protein (ENSP/NP_ .version or UniProt accession; product_of Transcript). Any statement placing a Gene where a Protein/Transcript is required (or vice versa) is a compile error E_BIO_ENTITY_KIND naming the required kind and the entity's known products, forcing explicit isoform selection. Feature kinds come only from the Sequence Ontology at a pinned release — the same rule GFF3 column 3 already imposes — so 'enhancer', 'exon', 'CDS' are SO accessions, not strings. | **rationale**: The gene-vs-product conflation is the classic biology modeling error the prompt names, and the fix costs nothing new: the standards ecosystem already assigns distinct accession spaces per level and already mandates SO for feature types; the IR transcribes that partition into nominal types, satisfying Gate 1 (features and molecules as typed objects, never generic predicates). | **alternatives_rejected**: A subtype hierarchy with Gene <: BioEntity and implicit widening (readmits the conflation through coercion); representing everything as a Sequence plus annotations (proteins and genes are not strings — a gene survives an assembly change, its sequence does not); free-text feature kinds (documentation-enforced convention = Gate 1 failure).
- **decision**: Variants, haplotypes, and structural variation: transcribe the VRS 2.0 class system as IR types, with normalization inside the compiler | **recommendation**: IR types Allele, SequenceLocation, CisPhasedBlock (VRS 2.0's rename of Haplotype), CopyNumberCount, CopyNumberChange, and the structural classes (Adjacency, Terminus, DerivativeMolecule) are transcribed from VRS 2.0.1, including its normalization algorithm, so that any two surface spellings of the same variant compile to the same ga4gh:VA digest — normalization is part of deterministic compilation, not a downstream service. HGVS and SPDI are accepted as surface input syntaxes, lowered to VRS at compile with the lowering recorded in the receipt; an HGVS string that is ambiguous under the pinned reference fails closed. | **rationale**: Variant identity is where biology's silent-corruption risk concentrates (same indel, five spellings); VRS solves it with an approved, versioned, digest-sealed normal form, and its 2.0 class set now covers structural variation, so the product need invent nothing. CisPhasedBlock gives haplotypes a typed home with the phasing semantics already specified. | **alternatives_rejected**: HGVS as the internal form (a notation, not a data model; normalization unspecified); VCF-tuple identity (reference-convention-dependent, no normalization, no digest); deferring structural variation (VRS 2.0 already ships it; excluding it would force escape hatches later — a Gate 1 failure mode).
- **decision**: Typing biological generalizations: context-scoped defaults AND statistical claims, both first-class; unscoped universals over biological kinds are compile errors | **recommendation**: A generalization over a biological kind must declare one of three quantifier forms. (a) universal — permitted only where the relation is definitional or mathematical (stoichiometry, sequence identity, type membership); the compiler maintains the whitelist of universal-eligible relations as schema content. (b) default_in(context, except: ExceptionClass) — a Cyc-style context-scoped default: valid only inside the named context (organism/strain/tissue/condition — an A.5.5 context record), with the exception class declared (enumerated instances, a typed subclass, or an open exception relation). Inside an assembled context it compiles to a classical guarded implication: rule applies to x unless exception(x); the exception relation is open-world, so a verdict that needs 'no exception applies' is capped at supported — unless the context owner has closed the exception relation per A.5.6, which upgrades to proved-in-context and cites the closure. Lifting a default out of its context is fail-closed: no declared lift ⇒ out_of_regime. (c) statistical(population: CohortRef, measure, value, uncertainty) — a frequency/penetrance claim bound to a first-class population/cohort entity, evaluated under the named statistical criterion (A.4). The compiler's action on a bare ∀ over a biological kind is E_BIO_UNSCOPED_UNIVERSAL, an error message that names all three repairs with syntax. GO's NOT-qualifier practice is the transcription precedent for (b)'s exception data: exceptions are curated positive assertions of absence, never inferred. | **rationale**: This is the only composition consistent with Stage A's rulings: classical logic inside assembled contexts, no paraconsistency, no default-true substrate (the exact choice that cost Cyc soundness and determinism), closure owner-only and cited, out_of_regime = failed lift. Biology's exception-richness is real but structural — it lives in the guard and the context scope, not in a nonmonotonic consequence relation. | **alternatives_rejected**: Default logic / circumscription in the core (unauditable proofs, the Cyc failure mode, and unfamiliar to every target user); universals-with-warnings (fail-open; the warning becomes wallpaper); statistical-only (many curated biological rules — 'mammalian cells require…' — have no defensible reference population and are genuinely context-scoped defaults); probability-annotated logic (collapses the seven separated uncertainty kinds into one number, explicitly banned).
- **decision**: Genotype–phenotype and homology claims: dedicated claim kinds that never compile to implications | **recommendation**: G2PClaim is a claim kind (A.5.1 discipline) with kind-mandatory fields: variant/genotype (VRS id or CisPhasedBlock), phenotype term (HPO/MONDO at a pinned release), inheritance mode, evidence code (ECO, as GO annotation already requires), source + version; penetrance, when quantified, is a statistical claim over a named population, never a logical rule. HomologyClaim likewise: relation kind (ortholog/paralog, from SO or a pinned orthology resource), method, source database + version. Neither claim kind licenses inference by default: transferring a function claim across a homology edge requires an explicit, declared lift (the A.5.10 lifting discipline), and a query that would need an undeclared transfer returns out_of_regime citing the missing lift. | **rationale**: The G2P and homology literatures are exactly where 'variant X causes phenotype Y' silently becomes a material implication and poisons downstream reasoning; typing them as evidence-bearing claims with mandatory ECO provenance keeps them queryable and citable without ever entering the deductive closure uninvited. | **alternatives_rejected**: Compiling pathogenicity to implication with a confidence weight (the banned collapsed score); excluding G2P from the vertical (the chem-bio reaction-network slice needs at least loss-of-function claims to state why a reaction is absent in a mutant); free-form phenotype strings (undeclared vocabulary is a compile error by product definition — HPO/MONDO are the transcription sources, flagged evidence-incomplete pending a governance check).
- **decision**: Large-artifact boundary: semantic threshold, content-addressed ExternalArtifact type, GA4GH digests where they exist | **recommendation**: The rule: an object stays in the KB iff it can appear as a term in a logical claim the reasoner may destructure; everything inference treats as opaque is external. Concretely — in-KB: entities, identifiers/digests, coordinates, VRS objects, reaction networks, claim metadata, context records. External, always: full-length sequences (referenced by refget SQ digest; an inline sequence literal is permitted up to a small fixed bound, recommend 1,000 residues, and is digested at compile regardless, so inlining is a spelling choice with zero identity consequence), reference sets (seqcol digest), alignments, images, raw datasets/matrices, VCF/BAM/FASTQ files. The mechanism is one IR type: ExternalArtifact { media_type, schema: SchemaRef (declared, versioned — a bare 'CSV' with no column schema is E_BIO_ARTIFACT_NO_SCHEMA), digest: (algorithm, value) with sha-256 for generic files and the GA4GH algorithm where the artifact class defines one, size, retrieval: hint-only (a URL is a hint, never identity) }. A dangling or digest-mismatched artifact reference fails closed at context assembly, not at query time. | **rationale**: The BioModels record is the controlling precedent from the local evidence base: name-based, advisory references produced dangling model files, NaN parameters, and stale URLs inside the curated corpus itself, and a 2025 repair campaign recovered only 88% — the product's hash-bound fail-closed ingest is precisely the absent mechanism. The semantic threshold (not a byte count) keeps the KB from ever growing a million residue-level facts while guaranteeing the reasoner never holds an unverifiable term. | **alternatives_rejected**: A pure size threshold (a 400-residue protein sequence and a 400-byte JSON blob have different logical status; size is a symptom); loading sequences as per-residue facts (the million-facts anti-pattern the prompt bans; no query the vertical needs destructures residues logically — alignment and matching are solver obligations, not deduction); URL-based references with checksums optional (the exact BioModels failure, re-shipped).
- **decision**: Assays and protocols as measurement context: OBI as the transcription source, BAO as the optional screening refinement | **recommendation**: The kind-mandatory context schema (A.5.5) for biological measurement claims requires: assay type (an OBI term at a pinned release), a protocol reference (typed artifact or citation), and a specimen entity (CellLine CVCL / tissue term / organism taxid + strain). BAO terms are accepted as an additional, more specific annotation axis for screening assays (format/technology/endpoint) without replacing the OBI slot. The compiler validates terms against the pinned ontology release exactly as it validates ChEBI in the chemistry half; a measurement claim missing the assay slot is E_BIO_NO_ASSAY_CONTEXT. | **rationale**: OBI is a full-membership OBO Foundry ontology whose declared scope is precisely investigation design, protocols, instruments, materials, and analyses — the external standard the transcription-only rule requires; the published OBI/BAO relationship ('different, but not incompatible') supports layering rather than choosing. Assay context is what makes the Crabtree-style regime checking (A.5.4) possible for biology: 'in-vitro at 2% glucose' is context data, not prose. | **alternatives_rejected**: Free-text protocol descriptions (fail-open); inventing a minimal in-house assay vocabulary (violates transcription-only governance and re-runs Cyc's judgment-curation economics); mandating BAO for everything (its scope is screening assays; forcing it onto physiology measurements would create exactly the escape-hatch pressure Gate 1 penalizes).
- **decision**: Pathways, complexes, and interaction networks: pathways are contexts/collections, not causal objects, in v1 | **recommendation**: Molecular complexes are typed compositional entities: a stoichiometric multiset of Protein/RNA/small-molecule members (each a typed entity), optionally cross-referenced to a GO cellular-component or Complex Portal accession — never a bare node name. Molecular interactions (binding, phosphorylation) are typed claims with mandatory detection-method vocabulary (PSI-MI as candidate transcription source — flagged evidence-incomplete, not fetched this task) and source+version. A 'pathway' in v1 is a named, versioned collection/context that imports a set of reactions and interaction claims (riding the chemistry half's reaction-network IR), not a first-class causal entity with its own inference rules; 'X is in the MAPK pathway' is membership in a cited collection, and any causal reading must be stated as reactions or as context-scoped defaults per the generalization rule. | **rationale**: Reaction networks are already the vertical's chemistry-side IR (SBML/COPASI precedent in the local evidence), so pathways-as-collections reuse that machinery with zero new logic; reifying pathways as causal objects is where pathway databases (KEGG-style maps) smuggle unattributed universals — the Path2Models experience (140k auto-generated models beside 1k verified) shows what happens when map-derived content isn't typed apart from verified content. | **alternatives_rejected**: First-class causal pathway objects with activation/inhibition edges as logic (untyped defeasible causality — reintroduces unscoped universals through the back door); adopting a single pathway database's schema as the IR (BioPAX is the obvious candidate but is OWL-shaped and fail-open on exactly the fields the product needs mandatory — revisit at Stage B with a fetched evaluation).

## adopt

GA4GH VRS 2.0.1 (approved 2025-03-27; classes Allele/SequenceLocation/CisPhasedBlock/CopyNumberCount/CopyNumberChange/Adjacency/Terminus/DerivativeMolecule; computed identifiers ga4gh:<prefix>.<base64url(SHA-512 left 24 bytes)>; interbase 0-based coordinates). refget Sequences v2.0.0 (ga4gh SQ digests, canonicalized uppercase A–Z; MD5 legacy, TRUNC512 deprecated). refget Sequence Collections v1 as approved 2025-03-27 (RFC 8785 canonicalization; inherent attributes names+sequences; comparison API). NCBI assembly accessions GCA_/GCF_ nine-digits.version, versioned independently, version bump on sequence change and (since 2024) sequence renaming. RefSeq accession.version (version increments iff sequence changes). Ensembl stable-ID.version (version increments on sequence/exon/splicing change). HGNC:# IDs as gene identity (symbols resolved at compile under a pinned genenames.org release). NCBI taxdump with merged.dmp/delnodes.dmp semantics, pinned per release. Cellosaurus CVCL accessions (=RRIDs) for cell lines, pinned per release. Sequence Ontology (pinned release) for feature kinds, as GFF3 column 3 already mandates. OBI (OBO Foundry full member) for assay/protocol typing, BAO as screening refinement. GO annotation practice: ECO evidence codes + reference mandatory; NOT-qualifier pattern for curated exceptions. RFC 8785 (JCS) and RFC 4648 base64url as the serialization substrate. SHA-256 for generic external artifacts where no GA4GH class digest exists.

## avoid

Symbols as identity (HGNC renames symbols, keeps IDs — symbol-keyed KBs silently re-bind across releases; the SEPT2/Excel failure class). Unversioned accessions (RefSeq/Ensembl/assembly versions all move; a bare GCF_ or NM_ is a claim about a moving target). Coordinate defaults (an undeclared 0-vs-1-based/half-open-vs-inclusive convention is biology's best-documented silent off-by-one corruption; BED/VCF/GFF all differ). Gene⇄product coercion (the classic conflation; makes 'the gene binds the promoter' and 'the protein binds the promoter' indistinguishable). Universal implications from biological generalizations (turns every exception into a derivable contradiction or a false theorem; Cyc's default-true substrate answer cost it soundness, determinism, and checkable proofs — the failure the monotonic core exists to avoid). Probability-weighted rules or any collapsed confidence score (banned by A.5.7). Name/URL-based artifact references (BioModels' curated corpus accumulated dangling files, NaN parameters, stale URLs; 2025 repair recovered only 88% — advisory provenance decays). Per-residue sequence facts (millions of facts encoding one string; alignment/matching are solver obligations, not deduction). Treating cell lines as organisms (HeLa is not Homo sapiens; ~8.6% of literature cell lines are on the problematic list). Reifying pathways as causal logic objects (imports unattributed universals from pathway maps — the Path2Models uncurated-volume trap). In-house digest or vocabulary invention (violates transcription-only governance; every entry must have a mechanizable external oracle).

- Does VRS 2.x ship a Genotype class (beyond CisPhasedBlock) adequate for diploid genotype claims, or does the product need a thin Genotype type over CisPhasedBlocks? (Not verified this task.)
- Governance ruling needed: do curated OBO ontologies (HPO, MONDO, UBERON, PSI-MI) qualify under 'transcription-only with mechanizable oracle'? The oracle 'term T exists in release R' is mechanizable, but term correctness is curated judgment — the rule's intent needs an owner ruling before Stage B commits phenotype/anatomy slots.
- The default_in compilation claim — that guarded classical implications plus owner-closed exception relations suffice for realistic biological rule sets without genuine nonmonotonic logic — must be exhibited on the vertical slice (same pre-registered pattern as the A.5.10 uncertainty-propagation trigger).
- Exact inline-sequence bound (recommended 1,000 residues) is a placeholder pending authoring-ergonomics evidence from the vertical slice.
- Whether VRS normalization (fully-justified/VOCA) is specified tightly enough in 2.0.1 to guarantee cross-implementation digest agreement for all indel classes, or whether the product needs conformance vectors (GA4GH publishes some — not fetched).
- Annotation drift under pinned accession.version: a RefSeq version fixes sequence but not annotation; whether feature claims need an additional annotation-release pin (e.g. RefSeq annotation release / Ensembl release number) beyond accession.version.
- BioPAX/Complex Portal/PSI-MI fetched evaluation for the interaction-claim vocabulary (all cited from memory or secondhand this task).
